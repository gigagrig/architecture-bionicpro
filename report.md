## Узкие места

Подробности и условия применения — в разделе
[«Ограничения и дальнейшие решения»](Task1/architecture.md#ограничения-и-дальнейшие-решения).

| Ограничение или риск | Основание и влияние | Следующий шаг |
| --- | --- | --- |
| Один процесс и общая блокировка | Сессии в памяти; сетевые операции под блокировкой сериализуют запросы, рестарт завершает сессии | Региональное общее хранилище и атомарные операции на отдельной сессии при масштабировании |
| Строгая ротация cookie | Старый ID отвергается сразу; гонки вкладок и потеря ответа могут потребовать нового входа | Согласовать модель нескольких вкладок; текущая очередь охватывает одну вкладку |
| Задержка отзыва доступа | Между обновлениями BFF использует проверенный access-токен до 120 секунд | Backchannel logout или интроспекция, если нужен немедленный отзыв |
| Защита внутренней сети и ключей | Внутренние HTTP/SQL не используют TLS; ключ профилей находится в .env; внешний токен хранится Keycloak | В эксплуатации — TLS, секрет-хранилище, шифрование дисков/копий и регламент ротации ключей |
| Права bind LDAP | Учебный bind использует администратора каталога | Выделенная запись только для чтения нужных OU |
| Возраст учебных зависимостей | OpenLDAP 1.5.0 и Create React App с устаревшими транзитивными пакетами | Отдельное обновление образа/сборки и проверка уязвимостей до промышленного запуска |
| Локализация — архитектурное решение | Страна второго представительства и её требования в условии не указаны | Выбрать страну и согласовать размещение, сроки хранения и правила доступа |

   [инструкции входа](Task1/authentication.md#сертификат-и-первый-вход).
3. **Реальная инфраструктура представительств:** региональная схема не была
   развёрнута в другой стране. Для этого отсутствуют адреса, провайдеры и
   согласованные правила обработки данных.

Пользователь получает отчёт только по своим протезам. В запросе нет допустимого

предыдущая успешная версия остаётся читаемой. Проверка готовности и чтение

Исправления по результатам интеграции:

- В Airflow `dags test` использует указанную дату как конец предыдущего
  дневного интервала. Ограничение общего времени запуска конфликтовало
  с исторической датой теста при работающем scheduler; вместо него установлено
  ограничение времени выполнения каждой задачи — два часа.
  Ручные тесты используют 12:00, чтобы не совпадать с логическими датами
  плановых запусков и backfill в 00:00. Выявлено, что переиспользование старого
  ручного запуска сохраняет его исходный интервал даже при сбросе задач;
  необходимые дни дополнительно проверены по реестру ClickHouse.
- Работающий Nginx потребовал reload для нового `/reports`; шаг добавлен
  в инструкцию обновления стенда.
- Настройки лимитов нельзя менять HTTP-параметрами при `readonly=1`;
  перенесены в профиль сервера без ослабления запрета записи.
- Устранена подмена Date строковым SQL-псевдонимом; UUID-массив теперь
  передаётся в ожидаемом ClickHouse текстовом формате, а не как JSON.

Ограничения проверки:

- Встроенный браузер отказал в открытии HTTPS-страницы из-за

  только локальному сертификату, TLS-проверка в нём включена. Шаги ручной
  проверки — в [инструкции](operations.md#ручная-проверка-интерфейса).
- Производственные CRM/Битрикс24, датчики и Android-клиент не предоставлены;
  интеграция проверена на явных учебных контрактах и синтетических данных.
- Нагрузочные испытания, проверка всех зависимостей на уязвимости,
  распределённая отказоустойчивость и юридическая локализация не проверялись.

## Узкие места

Подробности — [ограничения архитектуры](Task2/architecture.md#ограничения-и-дальнейшие-решения).

| Ограничение / потенциальный риск | Основание и влияние | Следующий шаг |
| --- | --- | --- |
| Массовое чтение транзакционной БД | ETL читает все события дня; индексы и потоковый курсор не устраняют нагрузку источника | Измерить промышленный объём и выбрать способ снижения нагрузки: реплику или доставку изменений |
| Память подготовки | Владение и агрегаты всех клиентов находятся в памяти рабочего процесса | Проверить большой дневной объём, при необходимости разделить выгрузку |
| Рост числа версий | Старые и неудачные batch сохраняются для согласованного чтения | Согласовать сроки хранения и безопасную очистку с учётом активных запросов |

  при оптимизации PREWHERE; введены безопасное чтение и отдельный запрет
  публикации при некорректных обязательных полях и временах.
- Connect REST может кратковременно отвечать 404/409/503 при регистрации
  и ребалансировке. Инициализатор ожидает устойчивый RUNNING с ограничением
  времени, скрывая ответ, который мог бы содержать служебные данные.
- Ожидание Compose для явно выбранных завершившихся одноразовых сервисов
  дало отказ несмотря на код 0. Инструкция разделяет общий запуск и проверку
  только постоянных сервисов; диагностика инициализаторов оставлена отдельно.

| Ограничение / риск | Основание и влияние | Следующий шаг |
| --- | --- | --- |
