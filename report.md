## Проверки

- Собраны контейнеры фронтенда, BFF и Keycloak с Java SPI-провайдером.
  `npm ci` и `npm run build` завершились успешно, Java-провайдер собран Maven.
- `docker compose config --quiet` — без ошибок. Основной стенд достиг состояния
  готовности при `docker compose up -d --wait`.
- [23 проверки серверной безопасности](bionicpro-auth/tests/test_security.py)
  прошли: PKCE, callback и повторное использование state, привязка к браузеру,
  подпись/issuer/audience/azp/срок JWT, nonce, cookie и ротация, обновление пары
  токенов, отказ refresh, CSRF, выход, сроки сессии и согласие на профиль.
- Сквозной сценарий с настоящим Keycloak подтвердил настройку OTP, вход,
  смену cookie, отклонение старого ID, CSRF-защиту, успешный запрос спустя
  122 секунды и закрытие доступа после выхода. При первом таком прогоне сам
  сценарий прошёл, но очистка временной записи получила 401 из-за истечения
  токена тестового администратора; тестовый клиент исправлен для его обновления.
- Полный повторный прогон [интеграционных тестов](bionicpro-auth/tests/test_live.py):
  **7 passed за 126,29 секунды**. Проверены локальный OTP-вход и refresh,
  отклонение неверного OTP, запрет входа без PKCE и через Password Grant,
  отказ обмена настоящего кода с неверным verifier, вход и эффективные роли
  `john.doe`, `jane.smith`, `alex.johnson` через LDAPS.
- Итоговый экспорт импортирован в отдельную чистую БД проекта
  `bionicpro-task1-export-check`; Keycloak достиг healthy. После проверки
  временный проект удалён, основной стенд оставлен работающим.
- Скрипты проверены через `python3 -m py_compile` и `-h`; подготовка локальных
  секретов и экспорт проверены фактическим запуском. Повторная подготовка
  сохранила существующие секреты и сертификаты.
- Финальная проверка JSON подтвердила PKCE S256, конфиденциальный клиент,
  обязательный OTP, lifetime 120 секунд, ротацию refresh и scope `broker/read-token`.
  Все локальные ссылки документов существуют; `git diff --check` — без ошибок.
- Обе страницы draw.io экспортированы и просмотрены. Исправлены перекрытия
  подписи SQL и связей, добавлен отдельный оператор производства, проверены
  границы регионов. В используемом draw.io номера страниц начинаются с 1.
- Выполнен отдельный второй проход по `architecture.md`, `README.md` задания,
  корневому README и диаграмме: сверены термины, роли, сроки, согласие и границы
  реализованных компонентов. Уточнены обязательный scope `basic`, хранение
  минимального идентификатора до согласия и доверенные прокси внутри стенда.
- При настройке выявлены и исправлены: формат LDAP-компонента для импорта,
  имя файла realm, параметр `roles.dn`, HTTPS-контекст внутренних запросов,
  обязательный `sub` access-токена через scope `basic`.

Ограничения проверки:

- Настоящий вход в Яндекс не выполнялся: в проекте нет Client ID/Client Secret
  зарегистрированного приложения. Брокер компилируется; запрос внешнего профиля,
  ограничение полей и шифрованная запись проверены с подменёнными ответами.
- Google Authenticator/FreeOTP на физическом телефоне не проверялись.
  Автоматические проверки используют TOTP того же формата.
- Встроенный браузер остановил визуальную проверку интерфейса на
  `ERR_CERT_AUTHORITY_INVALID`. Проверка сертификата не отключалась; тесты HTTP
  доверяют только созданному локальному сертификату. Шаги доверия сертификату и
  ручного входа приведены в [инструкции](Task1/README.md#сертификат-и-первый-вход).
- Сборочная цепочка React сообщает об устаревших зависимостях и Browserslist;
  автоматический аудит всех зависимостей на уязвимости не выполнялся.

## Узкие места

Подробности и условия применения — в разделе
[«Ограничения и дальнейшие решения»](Task1/architecture.md#ограничения-и-дальнейшие-решения).

| Ограничение или риск | Основание и влияние | Следующий шаг |
| --- | --- | --- |
| Один процесс и общая блокировка | Сессии в памяти; сетевые операции под блокировкой сериализуют запросы, рестарт завершает сессии | Региональное общее хранилище и атомарные операции на отдельной сессии при масштабировании |
| Строгая ротация cookie | Старый ID отвергается сразу; гонки вкладок и потеря ответа могут потребовать нового входа | Согласовать модель нескольких вкладок; текущая очередь охватывает одну вкладку |
| Задержка отзыва доступа | Между обновлениями BFF использует проверенный access-токен до 120 секунд | Backchannel logout или интроспекция, если нужен немедленный отзыв |
| Защита внутренней сети и ключей | Внутренние HTTP/SQL не используют TLS; ключ профилей находится в .env; внешний токен хранится Keycloak | В эксплуатации — TLS, секрет-хранилище, шифрование дисков/копий и регламент ротации ключей |
| Права bind LDAP | Учебный bind использует администратора каталога | Выделенная запись только для чтения нужных OU |
| Возраст учебных зависимостей | OpenLDAP 1.5.0 и Create React App с устаревшими транзитивными пакетами | Отдельное обновление образа/сборки и проверка уязвимостей до промышленного запуска |
| Локализация — архитектурное решение | Страна второго представительства и её требования в условии не указаны | Выбрать страну и согласовать размещение, сроки хранения и правила доступа |

## Нерешённые вопросы

1. **Реальный Яндекс ID:** необходимы реквизиты OAuth-приложения и подтверждённый
   callback. Код подготовлен, внешняя проверка остаётся незавершённой. Пользователь
   заполняет локальный `.env` и выполняет раздел
   [«Подключение Яндекс ID»](Task1/README.md#подключение-яндекс-id); передавать secret
   в чат не требуется. До этого провайдер выключен и кнопка скрыта.
2. **Проверка телефоном:** выполнить вход с Google Authenticator или FreeOTP по
   инструкции. При необходимости места и имена скриншотов указаны в разделе
   [«Ручные доказательства проверки»](Task1/README.md#ручные-доказательства-проверки).
3. **Реальная инфраструктура представительств:** региональная схема не была
   развёрнута в другой стране. Для этого отсутствуют адреса, провайдеры и
   согласованные правила обработки данных.

Отчётность, ETL, S3/CDN и CDC относятся к заданиям 2–4 и не реализовывались.
`/api/reports` проверяет сессию и возвращает 501; поддельных отчётов нет.
