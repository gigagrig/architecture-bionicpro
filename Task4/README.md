# Поток изменений и витрина BionicPRO

CDC (Change Data Capture) доставляет изменения CRM и телеметрии в ClickHouse.
После начального снимка Debezium читает журнал PostgreSQL, поэтому регулярная
подготовка отчётов не выполняет массовые запросы к исходным базам.

## Документы и реализация

1. [Конфигурация развёртывания Kafka и Kafka Connect в Docker Compose](../docker-compose.yaml) — сервисы `kafka` и `kafka-connect`.
2. [Конфигурация Debezium-коннектора для БД CRM](../debezium/crm-connector.json) в [каталоге debezium](../debezium/).
3. [SQL приёма данных через KafkaEngine и создания Materialized View для витрины ClickHouse](../clickhouse/cdc.sql).

## Устройство и решения

1. Два коннектора Debezium в Kafka Connect передают изменения источников
   в два упорядоченных топика Kafka. Постоянные позиции позволяют продолжить
   доставку после обычного перезапуска.
2. KafkaEngine принимает события в ClickHouse. Журнал сохраняет их,
   а материализованные представления рассчитывают последнее состояние строк,
   историю владения и дневные показатели с учётом обновлений и удалений.
3. Публикация требует завершённых транзакций, однозначного владельца,
   контрольных отметок готовности дней и свежих подтверждений работы
   обоих потоков. Повторная доставка не удваивает показатели.
4. Задача Airflow `publish_cdc` каждую минуту публикует готовые версии
   в `cdc_report_mart` и каталог S3. API на Go читает эту витрину только
   при отсутствии файла; [доставка S3/CDN](../Task3/README.md) сохраняет
   проверку владельца на каждом скачивании.

У Airflow и API нет сетевого доступа и паролей исходных PostgreSQL.
Начальный снимок и ведение журнала всё ещё нагружают источники, а полный
пересчёт представлений — ClickHouse. Один брокер Kafka не обеспечивает
отказоустойчивость; потеря журнала или позиции требует согласованного
восстановления. Эти ограничения существенны при переходе к реальным объёмам.

## Запуск и настройка

Используйте [быстрый запуск](../README.md#быстрый-запуск).
Интерфейс: `https://localhost:3443`; Airflow: `http://localhost:8085`.
Секреты находятся в локальном `.env`; подготовка и миграции сохраняют тома.

[Общее руководство](../operations.md) содержит запуск, демоданные и публикацию истории.
[Диагностика CDC](cdc-diagnostics.md) — проверки потока, разбор сбоев и восстановление.
