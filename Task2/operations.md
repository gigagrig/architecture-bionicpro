# Запуск отчётов BionicPRO

Сервис отчётов работает на Go; доставка использует [S3 и CDN](../Task3/architecture.md).
Источники переведены на [CDC в задании 4](../Task4/architecture.md): Debezium,
KafkaEngine и обновляемая materialized view формируют показатели в ClickHouse.
Airflow больше не читает PostgreSQL CRM или телеметрии.

[Базовая архитектура до CDC](architecture.md), [draw.io](bionicpro-reports.drawio),
[PNG](bionicpro-reports.png), [результаты задания 2](../report.md#задание-2--результаты-работы).

## Подготовка и запуск

Используйте [актуальные команды запуска задания 4](../Task4/operations.md#подготовка-и-запуск).
Они сохраняют существующие секреты и тома, добавляют миграции CDC и регистрируют
коннекторы. Основной адрес: `https://localhost:3443`; Airflow: `http://localhost:8085`.
Доверие сертификату и вход с одноразовым кодом описаны в
[задании 1](../Task1/operations.md#сертификат-и-первый-вход).

## Подготовка периода

Заполните учебные источники и опубликуйте завершённые дни по
[инструкции задания 4](../Task4/operations.md#демоданные-и-публикация-периода).
`bionicpro_reports` запускается каждую минуту; единственная задача `publish_cdc`
публикует готовые CDC-показатели и S3-каталог. Явный параметр `day` добавляет
исторический день и принудительно создаёт его новую версию. Прежний дневной
`backfill` заменён запуском `dags trigger --conf`.

Изменение ранее опубликованных данных обновляет версию автоматически.
Незавершённая транзакция или событие без однозначного владельца не разрешает
новую публикацию. До её успешного завершения используется прежний снимок.

## Получение и скачивание

1. Войдите в личный кабинет как `user1`.
2. Выберите начальную дату и конечную дату, **не включаемую** в отчёт.
   Для данных 29 сентября — 1 октября укажите `2026-09-29` и `2026-10-02`.
3. Нажмите «Получить отчёт». Таблица покажет только два протеза `user1`.
   У запасного протеза будут нули, отклик и заряд — «—».
4. Нажмите «Скачать отчёт JSON». Загружается актуальная версия через CDN;
   если витрина обновилась после показа таблицы, скачанный файл отражает новые данные.
5. Выйдите и войдите как `user2`: будет доступен только его протез.
6. Запросите день, который не опубликован Airflow. Интерфейс покажет
   сообщение с отсутствующими днями; частичный отчёт не формируется.

API использует `GET /api/reports?from=YYYY-MM-DD&to=YYYY-MM-DD`.
`GET /reports` на том же HTTPS-адресе — равнозначный публичный маршрут через BFF.
Оба требуют cookie серверной сессии. Передавать токены в браузере не нужно.
Параметры `user_id`, `subject` и любые другие, кроме `from`/`to`, запрещены.
Повторяющиеся параметры также отклоняются. Максимальный период — 31 день UTC.

## Автоматические проверки

Для Go нужны Go 1.22+ и доступ к загрузке закреплённой зависимости:

```bash
cd reports-api
go test -race ./...
go vet ./...
```

Для серверного прокси и сквозной проверки из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install -r bionicpro-auth/requirements-test.txt
PYTHONPATH=bionicpro-auth .venv/bin/python -m pytest \
  bionicpro-auth/tests/test_security.py bionicpro-auth/tests/test_reports.py -q
BIONICPRO_E2E=1 PYTHONPATH=bionicpro-auth .venv/bin/python -m pytest Task2/tests/test_reports_live.py -q
```

Сквозная проверка создаёт временные аккаунты и синтетические события,
выполняет настоящий DAG, проверяет чужие/свои данные и пропуски периода,
затем удаляет тестовые записи из источников и аккаунты. Витрина для временных
ID остаётся учебным артефактом до очистки версий. Нужен доступ к Docker.

Проверки публикации CDC внутри образа Airflow:

```bash
docker compose exec -e PYTHONPATH=/opt/airflow/dags airflow-scheduler \
  python -m pytest /opt/airflow/tests/test_etl.py -q
```

## Ручная проверка интерфейса

После добавления локального сертификата в доверенные откройте Chrome/Firefox,
перейдите на основной адрес и выполните шаги получения отчёта выше.
Проверьте читаемость таблицы, скачивание JSON, сообщение о недоступном дне
и отсутствие данных `user1` при входе `user2`. На узком экране таблица должна
прокручиваться горизонтально.

Фактический результат ручной проверки запишите в [report.md](../report.md).
