# Запуск отчётов BionicPRO

Сервис отчётов написан на Go; Airflow использует Python для ежедневной
подготовки витрины из учебных PostgreSQL CRM и телеметрии в ClickHouse.
[Архитектура](architecture.md), [draw.io](bionicpro-reports.drawio),
[PNG](bionicpro-reports.png), [результаты проверок](../report.md#задание-2--результаты-работы).

## Подготовка и запуск

Из корня репозитория:

```bash
python3 scripts/prepare-local.py
docker compose build
docker compose up -d crm_db telemetry_db clickhouse keycloak bionicpro-auth frontend gateway
docker compose --profile tools run --rm reports-seed --days 3
docker compose up -d --wait --wait-timeout 240
docker compose exec gateway nginx -t
docker compose exec gateway nginx -s reload
```

Подготовка добавляет недостающие секреты в `.env`, сохраняя ранее созданные
значения задания 1. Имена Compose-проекта и старых томов сохранены.
Учебный скрипт сопоставляет `user1`/`user2` с фактическими ID Keycloak, создаёт
три протеза, данные за три завершённых дня UTC и контрольные отметки готовности
источников. Повторный запуск не удваивает события. У `user1` два протеза:
один с измерениями, один без измерений; у `user2` один протез с измерениями.

Параметры подключения берутся из Compose. Скрипт не предназначен для
заполнения производственных БД. Базы и схемы создаются при первом запуске
новых томов; изменение SQL не мигрирует уже существующий том автоматически.

Основной адрес: `https://localhost:3443`. Доверие локальному сертификату и
первый вход с OTP описаны в [инструкции задания 1](../Task1/README.md#сертификат-и-первый-вход).
Учебные логины: `user1`/`user2`, пароль `password123`. При первом входе
нужно настроить приложение-аутентификатор.

Airflow: `http://localhost:8085`, логин `admin`, пароль `AIRFLOW_ADMIN_PASSWORD`
из локального `.env`. Это служебный интерфейс только на loopback; не публикуйте
его HTTP-порт в Интернет. PostgreSQL, ClickHouse и Go API не открывают портов
на хосте. Airflow работает с LocalExecutor — выполняет задачи локальными
процессами в контейнере scheduler.

## Подготовка периода

Активный DAG `bionicpro_reports` сам обработает последний завершённый день.
Расписание — ежедневно в 00:00 UTC; предыдущие дни автоматически не догружаются.
Для истории используйте backfill с датами из вывода `reports-seed`.
Начальная и конечная даты backfill **включаются**; каждая обозначает день данных:

```bash
docker compose exec airflow-scheduler airflow dags backfill bionicpro_reports \
  --start-date 2026-09-28 --end-date 2026-09-30
```

Пример соответствует запуску 1 октября 2026 года. Если запускаете позже,
замените даты на фактические три завершённых дня из вывода заполнения.
Не запускайте несколько backfill одновременно или одновременно с повторной
обработкой того же дня. В интерфейсе Airflow убедитесь, что обе задачи
`build_mart` и `publish` за нужные дни имеют состояние `success`.

Если дневной запуск начался до заполнения источников, `build_mart` откажет
из-за отсутствующей контрольной отметки. После заполнения откройте DAG → Grid,
выберите этот запуск, выделите `build_mart` и `publish` и выполните Clear,
чтобы разрешить повтор. Не выставляйте задачам вручную состояние Success:
это не создаёт витрину и не публикует данные.

Для проверки отдельно выбранного дня без ожидания расписания:

```bash
docker compose exec airflow-scheduler airflow dags test bionicpro_reports 2026-09-29T12:00:00+00:00
```

В `dags test` ручная дата обозначает конец предыдущего дневного интервала:
в этом примере обрабатывается **28 сентября**. Это отличается от даты
данных в запусках backfill. Время 12:00 отделяет ручной тест от запланированных
запусков в 00:00: Airflow может переиспользовать существующий запуск с той же
логической датой, даже если у него другой интервал данных.

Повторная обработка формирует новую версию показателей. Частично записанная
версия не становится доступна API. После позднего события, исправления
владельца или контрольной отметки повторите обработку соответствующего дня.

## Получение и скачивание

1. Войдите в личный кабинет как `user1`.
2. Выберите начальную дату и конечную дату, **не включаемую** в отчёт.
   Для данных 28–30 сентября укажите `2026-09-28` и `2026-10-01`.
3. Нажмите «Получить отчёт». Таблица покажет только два протеза `user1`.
   У запасного протеза будут нули, отклик и заряд — «—».
4. Нажмите «Скачать отчёт JSON». Скачивается тот же показанный набор данных.
5. Выйдите и войдите как `user2`: будет доступен только его протез.
6. Запросите день, который не опубликован Airflow. Интерфейс покажет
   сообщение с отсутствующими днями; частичный отчёт не формируется.

API использует `GET /api/reports?from=YYYY-MM-DD&to=YYYY-MM-DD`.
`GET /reports` на том же HTTPS-адресе — равнозначный публичный маршрут через BFF.
Оба требуют cookie серверной сессии. Передавать токены в браузере не нужно.
Параметры `user_id`, `subject` и любые другие, кроме `from`/`to`, запрещены.
Повторяющиеся параметры также отклоняются. Максимальный период — 31 день UTC.

## Автоматические проверки

Для Go нужны Go 1.22+ и доступ к загрузке закреплённой зависимости:

```bash
cd reports-api
go test -race ./...
go vet ./...
```

Для серверного прокси и сквозной проверки из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install -r bionicpro-auth/requirements-test.txt
PYTHONPATH=bionicpro-auth .venv/bin/python -m pytest \
  bionicpro-auth/tests/test_security.py bionicpro-auth/tests/test_reports.py -q
BIONICPRO_E2E=1 PYTHONPATH=bionicpro-auth .venv/bin/python -m pytest Task2/tests/test_reports_live.py -q
```

Сквозная проверка создаёт временные аккаунты и синтетические события,
выполняет настоящий DAG, проверяет чужие/свои данные и пропуски периода,
затем удаляет тестовые записи из источников и аккаунты. Витрина для временных
ID остаётся учебным артефактом до очистки версий. Нужен доступ к Docker.

Проверки трансформации внутри образа Airflow:

```bash
docker compose exec -e PYTHONPATH=/opt/airflow/dags airflow-scheduler \
  python -m pytest /opt/airflow/tests/test_etl.py -q
```

и отсутствие данных `user1` при входе `user2`. На узком экране таблица должна
прокручиваться горизонтально.

за выбранный день. Не показывайте секреты, OTP QR-код, токены или cookie.
