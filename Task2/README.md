# Отчётность BionicPRO

Личный кабинет показывает дневные показатели каждого протеза: число измерений,
движений и ошибок, средний и максимальный отклик, минимальный заряд батареи.
Отчёт доступен таблицей и в JSON за период до 31 дня UTC; конечная дата
в период не включается.

## Устройство и решения

- PostgreSQL CRM хранит клиентов, протезы и интервалы владения. Событие
  телеметрии относится к владельцу на момент измерения; запасной протез
  без событий получает нулевые счётчики.
- ClickHouse хранит готовые показатели. Airflow публикует неизменные версии
  только готовых дней; пропуск дня приводит к ответу `409`, а не к частичному
  отчёту.
- API на Go получает проверенный токен через серверную часть интерфейса
  `bionicpro-auth` и ограничивает чтение владельцем. Передать чужой
  идентификатор параметром запроса нельзя.
- В действующем стенде источники доставляются через [CDC](../Task4/architecture.md),
  а API возвращает ссылку на файл в [S3/CDN](../Task3/architecture.md).
  Airflow каждую минуту публикует показатели из ClickHouse и не читает CRM.

[Базовая архитектура](architecture.md), [C4 в draw.io](bionicpro-reports.drawio)
и [PNG](bionicpro-reports.png) сохраняют исходный вариант с ежедневной выгрузкой
до CDC. Контракт показателей и правила владения применимы к текущему стенду;
старое расписание и прямой ответ API со строками заменены решениями Task3–Task4.
Для CRM и датчиков используются учебные контракты; исходников Android-клиента нет.

## Запуск и использование

Запустите стенд по [корневому README](../README.md#быстрый-запуск),
заполните и опубликуйте [демопериод](../Task4/operations.md#демоданные-и-публикация-периода).
Откройте `https://localhost:3443`, войдите как `user1`, выберите период
и нажмите «Получить отчёт» или «Скачать отчёт JSON».

Подробные сценарии и команды проверок — в [руководстве](operations.md).
Результаты проверок — в [report.md](../report.md).
