# Проверка кеширования и прав скачивания

Перед проверкой запустите стенд и подготовьте демопериод по
[общему руководству](../operations.md). Команды выполняются из корня репозитория.
Схема взаимодействия описана в [архитектуре доставки](architecture.md).

## Каталог и политики S3

API использует `catalog/cdc-current.json`; копировать старый каталог
`catalog/current.json` не нужно. Задача `publish_cdc` публикует версии
и каталог. После отказа S3 следующий запуск повторяет запись каталога,
сохраняя версии неизменных дней. После изменения политик доступа выполните:

```bash
docker compose run --rm minio-init
```

## Автоматические проверки

Используйте [окружение Python](../operations.md#подготовка-окружения-python)
и запущенный стенд с доступным Docker:

```bash
BIONICPRO_E2E=1 PYTHONPATH=bionicpro-auth .venv/bin/python -m pytest \
  Task3/tests/test_cdn_live.py -q -s
```

Тест сравнивает число успешных запросов `reports_api` в `system.query_log`
ClickHouse: первый запрос добавляет один, повторный — ноль. Проверяются
`MISS → HIT`, отказ чужому пользователю при заполненном кеше, новый URL
и данные после публикации, отказ после выхода. Во время теста не выполняйте
другие запросы отчётов или ручную публикацию.

Временные аккаунты с OTP и синтетические записи источников удаляются после
проверки; версии витрины и S3-файлы остаются до очистки истории. HTTPS
проверяется по локальному сертификату.

## Ручная проверка

После доверия сертификату откройте браузер и DevTools → Network.

1. Получите отчёт. В JSON `/api/reports` должен быть относительный
   `download_url`, без строк, токенов и адреса MinIO.
2. В запросе `/cdn/reports/...` проверьте `200` и `X-Report-Cache: MISS`
   для нового файла. Повторное чтение того же файла должно дать `HIT`.
   Уже прогретый файл сразу даст `HIT`; новая публикация создаёт путь для проверки `MISS`.
3. Скачайте JSON кнопкой и сопоставьте протезы и показатели с таблицей.
4. Скопируйте ссылку и выйдите: она должна давать `401`, включая прогретый файл.
   Войдите как `user2` и откройте ту же ссылку: ожидается `403`.
5. Принудительно опубликуйте тот же день с параметром `day` и получите отчёт: путь должен измениться,
   новое чтение дать `MISS`, затем `HIT`. В Airflow Grid проверьте успешную задачу `publish_cdc`.
